# RIDE LOG のUI/UX設計メモ

単一HTMLの通勤ログアプリに、体感品質の観点を6つ持ち込んだ。
それぞれの観点が、画面のどの振る舞いに対応しているかを記す。

## Game Feel

入力に対する即時の手応えを作る。

- 記録ボタンは押した瞬間に縮み、離すと跳ね返る（`transform` の120ms遷移）。
- 記録開始は位置情報の取得を待たず、押した瞬間に「記録中」へ切り替える。
- GPSの精度をドットと文言で常に示す（取得中、良好、ふつう、弱い）。
- 距離が0.1km進むごとに数字を弾ませる。

## Juice

出来事の手応えを増幅する。派手さより、意味のある出来事にだけ足す。

- 開始時にボタンから波紋が広がる。
- 保存時は新しいカードがスライドインし、距離、時間、平均速度を0から数え上げる。
- 過去の記録を上回る距離なら「自己ベスト」バッジと専用トースト、長めの触覚を出す。
- 履歴を開くと、走行軌跡の線が始点から描かれていく。

## Microinteraction

ひとつの操作を、トリガー、ルール、フィードバック、繰り返しの単位で設計する。

- 終了は長押しにした。ポケットの中で誤って止まる事故を防ぐため、650msの進捗リングで残り時間を見せ、途中で離すと「長押しで終了します」と赤く示す。
- 削除は確認ダイアログをやめ、即時に消して「元に戻す」トーストで6秒間だけ取り消せるようにした。
- カードの開閉は矢印の回転で状態を示し、高さは `grid-template-rows` の補間で滑らかに変える。

## Motion Design

時間とイージングを3段階のトークンに限定し、画面全体で揃える。

- 速い（120ms）は押下や色の変化、標準（220ms）は状態の切り替え、遅い（380ms）は要素の出入りに使う。
- 減速カーブ、加減速カーブ、跳ね返りカーブの3種類だけを使う。
- 履歴の初回表示は1枚ずつ45msずらして現れる。
- `prefers-reduced-motion` が有効な端末では、すべての装飾的な動きと数え上げを止める。

## Haptics

触覚は操作の確定を伝える手段として、視覚と対にして使う。

- Androidは `navigator.vibrate` で、軽いタップ、成功、警告、達成の4パターンを鳴らす。
- iOS Safariには振動APIがないため、`<input type="checkbox" switch>` の切り替えで鳴る触覚を流用する。これはユーザー操作の中でだけ効き、端末や設定によっては鳴らない。
- 触覚が使えない環境でも、動作には影響しない。

## Onboarding

初回だけ、操作の説明と権限の意味づけを先に示す。

- 3つの手順（開始、長押しで終了、履歴）を番号付きで示す。
- 位置情報の許可ダイアログを出す前に、データが端末内にだけ保存されることを説明し、ボタンを押して初めて許可を求める。
- iOSのSafariで開いているときは、ホーム画面に追加する案内を出す。
- 一度閉じると `localStorage` のフラグで二度と出さない。

## 検証方法

`navigator.geolocation` と `navigator.vibrate` を差し替えたPlaywrightで、次の流れを自動確認している。

1. オンボーディングから開始し、位置を流し込んで距離とGPS表示が更新される。
2. 短押しでは止まらず、長押しで保存され、数字が数え上げられる。
3. 2回目の長い走行で「自己ベスト」が付く。
4. 削除して「元に戻す」で復元され、再読み込み後も残る。
5. Googleマップのスタブを当てた場合に地図が描かれ、キー無効時はSVGに戻る。
